# TV Screen

A Vetro Shard: see what the TV shows and drive it from the dashboard.

- **Picture or live view** of the whole screen (video and menus), fitted beside the remote or at 1x, 1.5x or 2x. The live view always asks for
  the best the TV gives (30 fps, quality 95, source resolution).
- **Take a picture** saves a 1920x1080 PNG through the browser's downloads (in live view: the current frame).
  This needs a Vetro whose Shard frame allows downloads (`sandbox allow-scripts allow-downloads`, as on this branch).
- **Full remote**: number pad, colour keys, playback, Settings, Guide, app keys. Holding a button is a real long press.
- **Keyboard**: sends this computer's keyboard to the TV, key by key. Open the text field on the TV first.
  Esc is Back, F1 to F4 are the colour keys.

## The `exec` permission

Used for: running the capture helper, starting and stopping the live-view helper (`tv-screen-shard-live`, MJPEG on
127.0.0.1:8096), sending key events (`dbus-send` to `org.enlightenment.wm Test.EventKey`), opening the Vetro
launcher. Key names are checked against a fixed list; nothing from a request reaches a command line.

## Files

- `index.js`: routes and the commands above.
- `page.html`, `capture.dll.b64`, `capture.runtimeconfig.json`: generated by `shards/build-tv-screen.py`
  (the remote is taken from the dashboard, the helper from `app/native/capture`). The helper is a .NET assembly;
  a bundle holds text only, so it travels as base64 and is unpacked to `bin/` at start.

## Limits

- Protected video (DRM streams, HDCP inputs) is refused by the TV; the visible windows are shown instead.
- Text fields ignore the plain minus key (the page sends keypad minus); underscore may not type everywhere.
- Characters come from the TV's own keyboard layout.
- Checked on a QN85A (Tizen 6). Not written for TVs without the root helper.
